    ```prisma
      provider = "sqlserver"

      provider = "prisma-client-js"

    ```
    Define all 25 models from Design §4.1–§4.25 with proper SQL Server data types matching Tasks 0.2.3–0.2.27:
    1. `Users` (§4.1): internalUserId (UUID, PK), externalSubjectId (Entra sub, unique), email, role (`USER` | `ADMIN`), timestamps. No password fields per DEC-02.
    2. `UserProfiles` (§4.2): userId (FK), name, phone, privacyPolicyVersion, privacyAcceptedAt, aiDisclosureAcceptedAt, timestamps.
    3. `Projects` (§4.3): id (UUID, PK), userId (FK), name, description, status (`ACTIVE` | `ARCHIVED`), archivedAt, analysisSynthesis (relation to `ProjectAnalysisSynthesis?`), timestamps.
    4. `ProjectLocations` (§4.4): id, projectId (FK, unique), rawInput, resolvedAddress, latitude, longitude, geocodingProvider, inputProvenance, coordinatesProvenance, timestamps.
    5. `ProjectImages` (§4.5): id, projectId (FK), storageKey, originalFileName, mimeType, fileSizeBytes, processingState (`ImageProcessingState`: `UPLOADED`, `QUEUED`, `PROCESSING`, `RETRYING`, `COMPLETED`, `FAILED`, `DELETED`), retryCount, timestamps.
    6. `ImageAnalysisResults` (§4.6): id, projectImageId (FK, unique, strict 1:1), spaceType, isInterior, facadeType, floorCount, architecturalStyle, visibleSurfaces (Json), naturalLightQuality, paintableRegions (Json), rawGeminiResponse (Json), safetyRefusalReason, analysisError, timestamps. State fields use `AnalysisState` (`AI_INFERRED`, `USER_CONFIRMED`, `USER_OVERRIDDEN`).
    7. `PaintBrands` (§4.7): id, name (unique), slug (unique), isActive.
    8. `PaintProducts` (§4.8): id, brandId (FK to PaintBrand), name, formulation, finishType, applicationScope (`INTERIOR`, `EXTERIOR`, `BOTH`), surfaceCompatibility (Json), isActive.
    9. `PaintShades` (§4.9): id, productId (FK to PaintProduct), shadeName, shadeCode, colourFamily, hexApprox, provenance (`Provenance`), isActive, timestamps.
    10. `PaintShadeSources` (§4.10): id, shadeId (FK to PaintShade), dataSourceId (FK to DataSource), retrievedAt, approvedBy, createdAt.
    11. `ClimateProfiles` (§4.11): id, projectLocationId (FK, unique), provenance, dataSourceId (FK to DataSource), retrievedAt, annualFreezeThawayCycles, timestamps.
    12. `ClimateObservations` (§4.12): id, climateProfileId (FK), month (1–12), avgTempCelsius, avgHumidityPct, totalRainfallMm, avgUvIndex, prevailingWindDir, avgWindSpeedKmh.
    13. `RecommendationRuns` (§4.13): id, projectId (FK), manufacturerId, applicationScope, scoringWeightsVersionId (FK to `ScoringWeightVersion`), scoringWeightsVersion (String snapshot), relaxationApplied (Json), paletteHarmonyApplied, status (`RunStatus`: `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`), timestamps.
    14. `Recommendations` (§4.14): id, runId (FK to RecommendationRun), shadeId (FK to PaintShade), rank (1–5), compositeScore, surfaceScope, explanation, isHarmonyReplacement, replacedCandidateId, createdAt.
    15. `RecommendationFactors` (§4.15): id, recommendationId (FK to Recommendation), factorName (`ScoringFactor` enum: 9 factors), score, weight, weightedScore.
    16. `Dealers` (§4.16): id, name, address, latitude, longitude, phone, state (`DealerState`: `VERIFIED_OFFICIAL`, `THIRD_PARTY_DISCOVERED`, `UNVERIFIED`), discoverySource, timestamps.
    17. `DealerBrands` (§4.17): id, dealerId (FK to Dealer), brandId (String). *Note gap: brandId lacks Prisma @relation to PaintBrand.*
    18. `DealerVerificationRecords` (§4.18): id, dealerId (FK to Dealer), verifiedBy, verifiedAt, sourceUrl, notes.
    19. `ImageGenerationJobs` (§4.19): id, projectImageId (FK to ProjectImage), recommendationRunId, status (`GenerationJobStatus`: `QUEUED`, `PROCESSING`, `RETRYING`, `COMPLETED`, `FAILED`), retryCount, failureReason, fallbackPromptId, geminiModel, timestamps. (Wave 3 schema entity).
    20. `GeneratedImages` (§4.20): id, jobId (FK to ImageGenerationJob, unique), storageKey, isIndicative, createdAt. (Wave 3 schema entity).
    21. `GeminiFallbackPrompts` (§4.21): id, name (unique), promptText, isActive, timestamps. (Wave 3 schema entity).
    22. `DataSources` (§4.22): id, name (unique), category, providerUrl, provenance, lastUpdatedAt, isActive.
    23. `AuditLogs` (§4.23): id, userId (FK to User, nullable), eventType, resourceType, resourceId, outcome, sourceIp, metadata (Json), createdAt.
    24. `ProjectAnalysisSynthesis` (§4.24): id, projectId (FK to Project, unique), spaceType, spaceTypeConfidence, isInterior, isInteriorConfidence, facadeType, floorCount, architecturalStyle, visibleSurfaces (Json), naturalLightQuality, paintableRegions (Json), aggregationMetadata (Json), provenance (`Provenance` default DERIVED), timestamps.
    25. `ScoringWeightVersion` (§4.25): id, version (unique), weights (Json mapping 9 scoring factors summing to 1.0), isActive (Boolean), description, createdBy, timestamps, relation to `recommendationRuns`.

    Enums: `UserRole`, `ProjectStatus`, `ImageProcessingState`, `AnalysisState`, `ApplicationScope`, `Provenance`, `RunStatus`, `ScoringFactor` (exactly 9 factors), `DealerState`, `GenerationJobStatus`.
