<task type="auto">
  <name>Task 1: Prisma 5 Schema Definition for SQL Server (All 17 Tables)</name>
  <files>prisma/schema.prisma</files>
  <read_first>.kiro/specs/paint-platform/design.md#4-database-schema, .planning/phases/01-foundation/01-RESEARCH.md</read_first>
  <action>
    Create `prisma/schema.prisma` configured with:
    ```prisma
    datasource db {
      provider = "sqlserver"
      url      = env("DATABASE_URL")
    }
    generator client {
      provider = "prisma-client-js"
    }
    ```
    Define all 17 tables from Design §4.1–§4.17 with proper SQL Server data types:
    1. `Users`: internalUserId (UUID, PK), externalSubjectId (Entra sub, unique), email, role (`USER` | `ADMIN`), timestamps. No password fields per DEC-02.
    2. `UserProfiles`: userId (FK), name, phone, privacyPolicyVersion, privacyAcceptedAt, aiDisclosureAcceptedAt.
    3. `Projects`: id (UUID, PK), userId (FK), name, description, state (`ACTIVE` | `ARCHIVED`), timestamps.
    4. `ProjectLocations`: id, projectId (FK, unique), rawAddress, postalCode, latitude, longitude, geocodingProvider, provenance, timestamps.
    5. `ProjectImages`: id, projectId (FK), blobUrl, originalFilename, fileSize, mimeType, state (`ImageProcessingState`: `UPLOADED`, `QUEUED`, `PROCESSING`, `RETRYING`, `COMPLETED`, `FAILED`, `DELETED`), timestamps.
    6. `ImageAnalysisResults`: id, projectImageId (FK, unique), roomType, architecturalStyle, surfaceMaterial, naturalLighting, paintableRegionsJson, confidenceScore, state (`AnalysisState`: `AI_INFERRED`, `USER_CONFIRMED`, `USER_OVERRIDDEN`), timestamps.
    7. `PaintShades`: id, manufacturer (`ASIAN_PAINTS`, `BIRLA_OPUS`, `NEROLAC`, `BERGER_PAINTS`), shadeCode, shadeName, hexCode, finishType, interiorExterior (`INTERIOR`, `EXTERIOR`, `BOTH`), isActive, timestamps.
    8. `PaintProducts`: id, paintShadeId (FK), productName, formulation, productUrl, isMvpCatalogue.
    9. `PaintShadeSources`: id, paintShadeId (FK), sourceUrl, catalogueVersion, retrievedAt, verifiedBy.
    10. `ScoringWeights`: id, version (unique), wClimateDurability, wUvResistance, wMoistureResilience, wArchitecturalStyle, wNaturalLighting, wRegionalAesthetic, wUserPreference, wFinishSuitability, wUndertoneHarmony, isActive, createdAt.
    11. `RecommendationRuns`: id, projectId (FK), scoringWeightsId (FK), scope (`INTERIOR`, `EXTERIOR`, `BOTH`), manufacturer, runAt.
    12. `Recommendations`: id, recommendationRunId (FK), paintShadeId (FK), rank (1-5), compositeScore, explanationText.
    13. `RecommendationFactors`: id, recommendationId (FK), factorName, factorScore, factorWeight, factorRationale.
    14. `Dealers`: id, name, address, latitude, longitude, phone, manufacturer, dealerState (`VERIFIED_OFFICIAL`, `THIRD_PARTY_DISCOVERED`, `UNVERIFIED`), timestamps.
    15. `ImageGenerationJobs`: id, projectImageId (FK), paintShadeId (FK), state (`QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`), attempts, promptUsed, fallbackUsed, timestamps.
    16. `GeneratedImages`: id, jobId (FK, unique), blobUrl, watermarked, timestamps.
    17. `AuditLogs`: id (BigInt/UUID), userId, eventName, entityType, entityId, detailsJson, ipAddress, userAgent, createdAt.
    Define all relevant foreign keys, composite indexes, and unique constraints.
  </action>
  <verify>Run `npx prisma validate` to confirm schema validity without syntax or type errors.</verify>
  <acceptance_criteria>
    - `prisma/schema.prisma` contains exactly the 17 tables matching Design §4
    - All enum types (`Role`, `ProjectState`, `ImageProcessingState`, `AnalysisState`, `ApplicationScope`, `DealerState`, `JobState`) are declared
    - Password hash fields are completely absent from the `Users` table
    - `npx prisma validate` returns exit code 0
  </acceptance_criteria>
  <done>Complete Prisma 5 schema defined and validated.</done>
</task>
